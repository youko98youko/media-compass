# メディアコンパス極 ― SaaSプロトタイプ

**本番システムではありません。** 仕様書「AIエージェント向けコーディング仕様書_v2」を根拠に、
「メディアコンパス極を実際に使ったらどんな体験になるか」を検証するための動くプロトタイプです。

## 起動方法

```bash
cd media-compass-saas-prototype
npm install
copy .env.example .env   # Windowsの場合。macOS/Linuxは cp .env.example .env
npm start
```

ブラウザで `http://localhost:3000` を開いてください。

### AI連携について

- `.env` に `OPENAI_API_KEY` を設定すると、AIヒアリング・記事構成・記事本文生成が実際のOpenAI API（ChatGPT、既定モデルはgpt-4.1）で行われます。
- 未設定の場合は **シミュレーションモード** で動作します。AI呼び出しの代わりにテンプレート応答を返しますが、
  ユーザーが入力した回答内容は実際に記事へ反映されるため、体験の流れそのものは確認できます。
- 画面右上のバッジで、現在どちらのモードで動作しているかが常に分かるようになっています。
- APIキーはサーバー側の環境変数としてのみ使用し、フロントエンド（HTML/JS）には一切含まれません。

### アカウントと施策のステータス管理（ローカル版のみ）

ローカル版では、アプリの利用にログイン（アカウント作成）が必須です。最初の画面でログインしたあと、「メディアを選ぶ」画面（既存メディアを分析する）に進みます。
（「新しくメディアを構築する」は、準備中です。）上部メニューの「施策管理」から、施策（やること）の進み具合を管理できます。ログインしていないと、メディア分析・記事作成などのAPIも使えません。

- 施策の登録・変更（施策名・メモ・ステータス）・削除・一覧表示ができます。ステータスは「未着手／対応中／確認待ち／完了」の4種類で、ステータス別に絞り込めます。
- 施策は、ログインしたアカウントごとに分かれて保存されます。他のアカウントの施策は、見ることも変更することもできません。
- データは `data/accounts.json` に保存され、サーバーを再起動しても残ります（`.gitignore` で除外済み）。パスワードは scrypt でハッシュ化して保存します。
- ログイン状態も `data/accounts.json` に保存されるため（Cookieの値そのものではなく、そのハッシュだけを保存）、サーバーを再起動しても、ログインしたままです（有効期間は7日間）。有効期限が切れた場合は、どの画面でも、自動でログイン画面に戻ります。
- 公開環境（Render）では、この機能は自動的に無効になります（メニューも表示されません）。ローカルで使わない場合は、`.env` に `ACCOUNTS_ENABLED=0` を設定してください。

### 挿入画像の自動生成

AI連携中は、記事の編集画面を開くと、記事内の画像（アイキャッチ・挿絵）がOpenAIの画像生成で上から順に自動生成されます。
各画像の「再生成」で作り直せます。1枚生成するごとにOpenAIの利用料がかかるため、1記事あたりの生成回数に上限（既定15回）があります。
生成した画像はサーバーのメモリ上に保持されます（再起動で消えます）。`.env` の `OPENAI_IMAGE_MODEL`（既定 `gpt-image-1`）、
`OPENAI_IMAGE_QUALITY`（`low`／`medium`／`high`。既定 `medium`）、`IMAGE_MAX_PER_SESSION` で調整できます。
※ `gpt-image-1` は、OpenAI側で組織の確認（Verify Organization）が必要な場合があります。

### WordPress連携（下書き投稿）

「設定」画面、または記事の「WordPressに下書き保存」を押したときの接続画面で、サイトURL・ユーザー名・アプリケーションパスワードを入力すると、
実際のWordPressに接続できます（画面に、アプリケーションパスワードの発行手順が表示されます）。
接続方式は2つあります。
- **アプリケーションパスワード（REST API）**：WordPress 5.6以降。おすすめです。
- **ログイン用パスワード（XML-RPC）**：5.6より前の古いサイト向け。アプリ専用に作った、権限が「投稿者」のユーザーで接続してください（管理者のアカウントは使わない）。XML-RPC が有効なサイトが条件です。

接続画面で、サイトがアプリケーションパスワードに対応していないと分かった場合は、XML-RPC方式を案内します。
WordPressに接続しない場合は、編集画面の「WordPress用のHTMLを書き出す」で、タイトル・本文HTML・画像をコピー＆保存して、手作業で貼り付けられます。
記事は常に「下書き」として投稿され、アプリから公開することはありません。生成した画像は、先にメディアライブラリへアップロードされ、
1枚目（アイキャッチ）は「アイキャッチ画像」に設定されます。入力した情報はサーバーのメモリ上にだけ保持され、ブラウザには保存されません。
公開環境（Render等）では、パスワードの入力は推奨しません。

### GSC連携の設定（実連携するとき）

Google Search Console との連携（OAuth）は実装済みです。「既存メディアを分析する」→「GSCと連携して分析する」の画面で、
Google Cloud で発行したOAuthクライアントの **クライアントID・クライアントシークレット** を入力すると、実際にGoogleと連携できます
（画面に発行手順と、Google Cloudに登録するリダイレクトURIが表示されます。入力せずに「デモで続ける」で体験することもできます）。
入力した情報はサーバーのメモリ上にだけ保持され、ブラウザには保存されません。公開環境（Render等）では、シークレットの入力は推奨しません。

OAuthクライアントの発行手順（画面にも同じ手順が表示されます）：

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作成し、「Google Search Console API」を有効化する。
2. 「OAuth同意画面」を設定する（ユーザーの種類：外部。公開前の「テスト」状態では、テストユーザーに登録したGoogleアカウントだけが連携できる）。
   スコープは `.../auth/webmasters.readonly`（読み取り専用）、`openid`、`email`。
3. 「認証情報」→「OAuthクライアントID」（種類：ウェブアプリケーション）を作成し、「承認済みのリダイレクトURI」に
   `http://localhost:3000/api/gsc/callback`（公開環境では `https://（公開URL）/api/gsc/callback`）を登録する。
4. 発行されたクライアントIDとシークレットを、連携画面に入力する。毎回入力せずに済ませたい場合は、`.env` に `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`（必要なら `GOOGLE_REDIRECT_URI`）を設定すると、入力欄が出ずにGoogleの認証画面へ進みます。
5. 連携に使うGoogleアカウントは、対象サイトのSearch Consoleで権限（所有者・フルユーザー等）を持っている必要がある。

連携後は、分析するGSCプロパティを選び、過去28日分の検索クエリ・ページ別の実績・同一クエリで複数ページが表示されている候補（カニバリゼーション）を取得してAI分析に加えます。
連携情報（Googleのトークンや、入力したクライアントシークレット）は、ログインしているアカウントに紐づけて、**暗号化して** `data/accounts.json` に保存されます（AES-256-GCM。鍵は `data/secret.key`、または環境変数 `DATA_ENCRYPTION_KEY`）。
一度連携すれば、サーバーを再起動しても、新しい分析を始めても、連携画面に「連携済みアカウント」が表示され、そのアカウントで進められます（別のアカウントへの切り替え・解除もできます）。
※鍵ファイルが同じパソコン内にあるため、「ファイルを見られても、そのままでは読めない」程度の保護です。`data` フォルダは、他の人に渡さないでください。
※OAuth同意画面が「テスト」状態の間は、Googleの仕様で、連携から7日ほどでトークンが失効します。その場合は、「別のアカウントで連携し直す」から、もう一度連携してください。
一般公開での利用にはGoogleのアプリ審査（機密スコープ）が必要になる場合があります。

## 体験できる流れ

0. **起点（メディア状態判定〜方向性設計）**：「既存メディアを分析する」／「新しくメディアを構築する」を選択 → メディア理解（既存はサイトURL・GSC連携の疑似分析、新規は事業内容の入力＋AIヒアリング） → メディアの方向性・テーマ領域の確認
1. ダッシュボード：「今、作るべき記事テーマ」を選ぶ（0で設計した方向性を踏まえた提案として表示）
2. テーマ詳細の確認
3. 一次情報（自社の実績・お客様の声）の確認
4. AIヒアリング（最大3問。実際に会話できます）
5. 記事構成の生成・確認
6. 記事本文の生成（一次情報・ヒアリング回答を反映）
7. 画像・図解・表・引用・CTA等の装飾（画像は仮のプレースホルダー画像です）
8. 記事の確認・編集（見出し・本文はクリックして直接編集可能、段落の再生成も可）
9. 公開 → 実際のメディア記事のようなページとして表示
10. 公開後の監視状態の確認、および「今、直すべき記事」からのAIリライト体験（簡易版）

## 本番仕様との違い（プロトタイプ用の割り切り）

以下は「本番の正式仕様」ではなく、UX検証のための仮実装です。

| 項目 | プロトタイプでの扱い |
|---|---|
| 既存メディアの分析 | AI連携中は、入力したサイトURLを実際に簡易クロール（sitemap等から記事を取得し、代表20本のタイトル・見出しを読み取り）してChatGPTが分析。シミュレーションモード（公開デモ）では固定のデモ結果。GSC連携はGoogle認証情報の設定時のみ実連携（未設定の間は疑似で、検索クエリはデモ値） |
| テーマ候補 | AI連携中はChatGPTが方向性・事業情報から生成（検索ボリューム・競合はAI推測値）。シミュレーションモードでは固定デモ |
| 一次情報・既存記事の劣化データ | 固定のデモデータ（架空の外壁塗装会社）。事業ヒアリングの回答は一次情報として記事作成に引き継ぎ |
| 画像生成 | AI連携中は、OpenAIの画像生成（既定 gpt-image-1）で挿入画像を自動生成。シミュレーションモードでは仮のプレースホルダー画像 |
| CMS連携・公開 | WordPressに実接続した場合は、記事を「下書き」として投稿（公開はWordPress側で行う）。未接続（デモ）の場合は、アプリ内の疑似メディアページを生成 |
| ユーザー管理・権限・課金 | 実装なし |
| データ保存 | サーバーのメモリ上のみ（再起動で消えます） |
| 「今、直すべき記事」の順位・流入データ | 仕様書記載の表示例をそのまま使用した固定デモ値 |

これらの箇所は、仕様書上でも「未定」または本プロトタイプの対象外として扱っています。

## ネットに公開する方法（例：Render）

このプロトタイプは、PORT環境変数に対応済み・APIキーはサーバー側環境変数のみ使用という作りになっているため、
特別な改修なしに一般的なNode.jsホスティングサービスへデプロイできます。無料枠のあるRenderを例に説明します。

1. **GitHubにリポジトリを作る**：GitHubで新しい空リポジトリを作成し、このフォルダ（`media-compass-saas-prototype`）の中身をpushする。
   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/【自分のアカウント】/【リポジトリ名】.git
   git push -u origin main
   ```
2. **Renderにサインアップ**：https://render.com にアクセスし、GitHubアカウントでサインアップする。
3. **Web Serviceを作成**：ダッシュボードで「New +」→「Web Service」→ 先ほどのリポジトリを選択。
   - Build Command: `npm install`
   - Start Command: `npm start`
   - Instance Type: Free
4. （任意）実際のAIを使いたい場合のみ、Renderの「Environment」タブで `OPENAI_API_KEY` を設定する。
   **未設定のままなら、シミュレーションモードとして誰でも安全に試せます。**
5. デプロイが完了すると、`https://（サービス名）.onrender.com` のようなURLが発行され、誰でもアクセスできるようになります。

### 公開する際の注意点

- **認証機能はありません。** URLを知っている人は誰でも操作できます（このプロトタイプはデモ用の架空データのみを扱うため、機密情報は含まれません）。
- **無料プランはしばらくアクセスがないとスリープします。** 次のアクセス時に数十秒起動待ちが発生することがあります。
- **データはメモリ上のみの保存です。** サーバーの再起動・再デプロイで、公開した記事などのデータは消えます（本プロトタイプの想定どおりの割り切りです）。
- `OPENAI_API_KEY` を設定して公開する場合、認証のない公開URLから誰でもAPIを呼び出せる状態になるため、利用量やコストに注意してください（迷う場合は未設定のままシミュレーションモードで公開することを推奨します）。
